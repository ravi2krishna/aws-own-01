            through Low Latency & High Speed Internet Connections 

            -> NOTE: Properly Designed Applications will always utilize Multiple 
            Availability Zones for High Availability & Fault Tolerance

            -> A Content Delivery Network (CDN) is a geographically distributed 
            group of servers that caches content (images, videos, HTML, JavaScript) 
            closer to end-users, reducing latency and accelerating page loads. 
            By delivering data from nearby "edge servers" rather than a single origin server.

    -> Virtual Private Cloud - VPC 

        -> A  Virtual Private Cloud is a secured & isolated private cloud, 
        hosted within the public cloud.

        -> VPC is a service that lets customers(IBM) provision a 
        logically isolated section of the AWS Cloud where ibm can launch 
        AWS resources(Servers) in a VIRTUAL NETWORK that ibm define.

        -> NOTE: Having a vpc is similar to having your own data center inside AWS

        -> VPC is the Backbone of AWS Infrastructure

        -> NOTE: https://media.licdn.com/dms/image/v2/D4D12AQFI8sqvP4xFFQ/article-cover_image-shrink_720_1280/article-cover_image-shrink_720_1280/0/1700537758681?e=2147483647&v=beta&t=zE97TFGw5FQJEjUksqx7SohNsqqV57-IYQ_pj7K2M2U

    
    -> VPC Components

        -> Internet Gateway (IGW)

            -> Entry and Exit Point For (VPC)

            -> An IGW must be attached to a VPC if the resources inside the VPC need to 
            connect to resources via the open internet.

        -> Subnets 

            -> A Subnet ia logical subdivision of VPC 

            -> A Public Subnet can be reached from Internet

            -> A Private Subnet cannot be reached from Internet

        -> Route Tables 

            -> A route tables contains set of rules called Routes,
            which determine how the traffic to be directed.

            -> Public Route Tables contains internet based route

            -> Private Route Tables contains local / intranet route 

        -> Network Access Control Lists - NACL's 

            -> Subnet Level Firewalls 

            -> Subnet is group of Servers 

            -> By default everything is allowed inside subnet via NACL 

            -> NACL Have ALLOW / DENY Rules 

        -> Security Groups 

            -> Server Level Firewall

            -> Ever Server by default is ALL BLOCKED 

            -> section Groups ONLY ALLOW

    -> Subnetting

        -> Subnetting is the practice of dividing a network into two or more smaller networks.

        -> When you create a VPC, you must specify a CIDR (Classless Inter Domain Routing) block for the VPC.

        -> The allowed block size is between a /16 netmask (65,536 IP addresses) and 
        /28 netmask (16 IP addresses).

        -> CIDR Chart Reference - https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcTS6k6zXee9c6jv7fClL8vtD51-dnrOsrHfp58znU5hPEFYFDpK_tS2g2o&s=10

        -> AWS recommends to create a CIDR with 10.0.0.0/16 for future purpose

        -> The first four IP addresses and the last IP address in each subnet CIDR block are not available for you to use, and cannot be assigned to an instance.
            
            -> 10.0.0.0: Network address.
            -> 10.0.0.1: Reserved by AWS for the VPC router.
            -> 10.0.0.2: Reserved by AWS for Amazon DNS server.
            -> 10.0.0.3: Reserved by AWS for future use.
            -> 10.0.0.255: Network broadcast address.

Class - 9 
==========

    -> When We Create Instance By Default We Get Root Volume (Primary OS Disk)

    -> Additionally we can add more volumes i.e Additional Volume (Secondary Disk)

    -> When We Create Snapshot From A Volume, We Cannot Use Snapshots Directly 

        -> Using Snapshots We Need To Create Volumes Once Again 

    -> Every EC2 instance must have a root volume(Primary Disk), 
    but Additional Volume(External Disk) is Optional.

    -> Any additional volume can be attached or detached from 
    instance at any time, but not possible for Root Volumes,
    if you want to detach root volume, only after stopping instance
    we can detach root volume

    -> Root or Additional Volumes, size cannot be decreased 
    once created, meaning only scaling up is possible.

    -> Create Snapshots

    -> Create AMI's 

        -> NOTE: Applicable For Root Volumes Only 

        -> We Cannot Create AMI's For Additional Volumes 

    
    -> AMI's - Snapshots are Linked To EBS Volumes 

    -> NOTE: EBS Limitations 

        -> Using EBS We Cannot Get Data Directly Across Multiple Zones 

        -> Using EBS We Cannot Connect To Multiple Instances At Same Time 
        
        -> Using EBS We Can Only Scale Up, No Scale Down Possible

        -> Using EBS We Can Only Scale Up to TB's (65536 GB) 

    
    -> EFS Storage (Cloud Native NFS)

        -> Elastic File Storage 

        -> NOTE: All the above EBS Limitations can be 
        resolved using EFS. 

        -> EFS Cannot Be Used as Root Volume 

        -> AWS EFS Provides Fully Managed NFS File System 

        -> In EFS, You Only Pay For What You Use 

            -> In EBS We Created 500 GB, but used only 100 GB, 
            we are billed for 500 GB. 

            -> In EFS What you are using, you will be billed 
            only for useable storage (100 GB)

                -> Being Elastic, auto expands when we add data,
                auto shrinks when we delete data


        -> Using EFS We Can Get Data Directly Across Multiple Zones 

        -> Using EFS We Can Connect To Multiple Instances At Same Time 
        
        -> Using EFS We Can Only Scale Up and Scale Down Possible

        -> Using EFS We Can Scale Up to PB's (8 exabyte i.e 8000 PB's)

        -> EFS Uses Port 2049, it's not for Instances, this is for 
        EFS File System.

        -> To access EFS file system in VPC, 
        you can create one or more mount targets in the VPC 

        -> If there are multiple subnets in an AZ, 
        you can create a mount target in one of the subnets,
        then all the instances in that AZ will share the mount target.

        -> AWS recommends that you create mount targets in all the AZ's, 
        so that you can easily mount the file system on EC2 instances 
        that you might launch in any zone in future, 
        as there are no charges for mount targets

        -> https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcSWDK7vWWgkjJ-6s3I2OCUPOA62JX6gOC9sENZkGlQBSQ&s=10

        -> https://aws.amazon.com/s3/

        -> Object storage built to retrieve any amount of data from anywhere.

        -> S3 Is Internet Based Storage 

        -> S3 Buckets & S3 Objects 

        -> S3 Bucket 

            -> Data is stored in Buckets i.e they are main storage containers.

            -> Buckets have no size 

        
        -> S3 Objects 

            -> An Object is File 

            -> You can keep Unlimited Objects In Bucket

            -> But Max Size For an individual Object is 5 TB 

            -> S3 Objects Can Be Stored Across Multiple Zones 
            For High Availability. 

        
        -> NOTE: By default all Buckets and Objects are Private. 

            -> To Allow Access We Need To Enable Multiple Permissions 

                -> On Bucket Level Permissions Turn Off - Block all public access

                -> On Bucket Level Permissions -  Edit Access control list (ACL)

                -> On Bucket Level Permissions - In ACL's Allow List & Read Access 

                -> Go To Respective Object - Permissions - Access control list (ACL)
                    In ACL's Allow List & Read Access

            Amazon S3 Standard
